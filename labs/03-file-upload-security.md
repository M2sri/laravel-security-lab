# Lab 03: File Upload Security in Laravel

## What is file upload security?

File upload security is the practice of treating uploaded files as untrusted input. A safe upload flow validates the file, limits size, stores it outside the public web root, and serves it through application-controlled routes.

This lab focuses on defensive Laravel patterns for document uploads.

## Common mistakes

- Accepting any file type.
- Skipping MIME and extension validation.
- Allowing very large files.
- Storing uploads under `public/`.
- Trusting `getClientOriginalName()`.
- Serving files directly without authorization.

## Vulnerable example

This example is for learning only. It accepts any uploaded file, trusts the original filename, and stores the file publicly.

```php
$request->file('document')->move(
    public_path('uploads'),
    $request->file('document')->getClientOriginalName()
);
```

## Secure implementation

The lab route validates a PDF MIME type and extension, limits the file to 2 MB, lets Laravel generate a random filename, and stores the file on the `private` disk.

```php
$request->validate([
    'document' => ['required', 'file', 'mimes:pdf', 'extensions:pdf', 'max:2048'],
]);

$storedDocumentPath = $request->file('document')
    ->store('documents', 'private');
```

Controlled downloads should also be routed through application code:

```php
Route::middleware('auth:customer')->group(function () {
    Route::get('/labs/file-upload-security/download', function (Request $request) {
        $downloadPath = $request->validate([
            'path' => ['required', 'string', 'starts_with:documents/'],
        ])['path'];

        abort_unless(Storage::disk('private')->exists($downloadPath), 404);

        return Storage::disk('private')->download($downloadPath);
    });
});
```

For temporary sharing, prefer a signed application route that still validates the path and checks access before returning the file.

## Real-world SaaS examples

- Invoice platforms often allow customers to upload PDF tax documents or receipts.
- HR tools may accept private identity or onboarding documents.
- CRM systems may store customer contracts that should only be visible after an application access check.

In each case, private storage and authorized downloads matter because the files can contain sensitive business or personal data.

## Defensive testing approach

- Upload a valid PDF and confirm it is stored on the private disk.
- Upload a non-PDF and confirm validation rejects it.
- Upload an oversized PDF and confirm validation rejects it.
- Confirm the stored filename is generated by Laravel instead of copied from the client.
- Confirm unauthenticated users cannot download private files.
